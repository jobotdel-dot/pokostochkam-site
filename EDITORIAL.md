# Правила редакции — «По косточкам»

## Главное в двух предложениях

Разбор пишется **простым языком, как для умного пятиклассника**: короткие
предложения, без канцелярита, без юридического жаргона без пояснения.
Каждая цифра — **проверенная**, с примером расчёта в бухгалтерской практике
и ссылкой на первоисточник.

**Ни одной выдуманной цифры.** Если числа не нашли в первоисточнике — статья
не выходит.

---

## 1. О чём пишем

### Фильтр: три «да»

Тема берётся, если проходит **три фильтра**:

| Фильтр | Вопрос | Пример «да» |
|---|---|---|
| **Срок** | Есть дата, до которой надо что-то сделать? | срок сдачи 26 октября, срок уплаты, дата вступления в силу |
| **Цифра** | Можно показать расчёт с числами? | код тарифа, ставка, лимит, сумма взноса |
| **Ошибка** | Есть ошибка, из-за которой прилетает требование? | взяли в базу выручку с НДС, забытый код тарифа |

- **Три «да»** — публикуем первой.
- **Два «да»** — публикуем в обычном порядке.
- **Одно «да»** — не публикуем.

### Не берём

- Новости без срока и без цифр.
- Обзоры 1С — там нужна лицензия и практика, это другая профессия.
- Темы, где срок уже прошёл.
- «Образцы» без разбора ошибок: образец формы без объяснения, что в ней
  чаще всего заполняют неправильно, пользы не несёт.

---

## 2. Как пишем

### Язык

- **Предложение — до 20–25 слов.** Длинное разбивайте на два.
- **Глагол в начале:** «Сдавайте декларацию», а не «Декларация должна быть сдана».
- **Без канцелярита:**

| Не надо | Надо |
|---|---|
| осуществляется | делают |
| является | есть |
| данный | этот |
| указанный | тот, про который говорим |
| вышеуказанный | этот |
| имеющийся | тот, который уже есть |

- **Термин объясняем при первом употреблении:**
  «единый налоговый счёт (ЕНС)», «расчёт по страховым взносам (РСВ)»,
  «книга учёта доходов и расходов (КУДиР)».
  Линтер проверяет это автоматически.

### Цифры

- **Только точные.** Не «около 1000 ₽», а «1 000 ₽».
- Каждая цифра — из первоисточника, с указанием, откуда: номер статьи,
  пункт, приказ.
- Если считаете сами — покажите расчёт: `3 000 000 × 100 : 122 = 2 459 016,39 ₽`.
- Не округляйте так, чтобы менялся смысл. «24 383,70 ₽» — это 24 383,70 ₽,
  а не «около 24 тысяч».

### Примеры

- **Три примера с расчётом.** Минимум — один с полным разбором, максимум три.
  Читателю нужен выбор: «у меня такая сумма — что делать».
- Пример из практики, а не из учебника: «ИП на УСН „Доходы“ получил аванс
  610 000 ₽ с НДС…» — не «сумма X умножается на Y».
- В примере должно быть **развитие ситуации**: что было, что сделали, чем
  закончилось, а если ошиблись — чем грозит.

## 3. Структура статьи

Обязательные блоки — их проверяет линтер:

```
# Заголовок — как вопрос, на который человек ищет ответ
   (не «Новые коды РСВ», а «Какой код тарифа ставить в РСВ с 2026 года»)

@kicker: рубрика · тема
@desc:   одно предложение для сниппета в поиске
@lead:   2–3 предложения для первого абзаца на странице

## Ситуация
   2–3 предложения: кто, что сделал, из-за чего вопрос.
   Можно с цитатой вопроса.

## Что говорит закон
   Что именно говорит норма. Со ссылкой на статью.
   Не пересказ кодекса, а ответ на вопрос читателя.

## Что делать по шагам
   5–7 шагов. Глагол в начале. Каждый шаг — одна строка.

## Примеры
   :::example — разбор расчёта с числами
   Сколько таких блоков — решаете сами, но хотя бы один обязателен.

## Ошибки и подводные камни
   Что приводит к требованию ФНС. Это то, за что читатель возвращается.

## Нормы и источники
   НПА + номера пунктов + ссылки на pravo.gov.ru / nalog.gov.ru.
   Ссылки обязательны — без них статья не публикуется.

*Материал носит информационный характер и не заменяет консультацию
по конкретной ситуации.*
```

### Блоки-акценты

| Блок | Когда использовать | Как выглядит |
|---|---|---|
| `:::example` | разбор конкретного расчёта | карточка с примером |
| `:::judgment` | профессиональное мнение, как поступить | карточка «Совет» |
| `:::checklist` | что проверить перед сдачей | карточка «Красный флаг» |

## 4. Как проверяем (обязательный шаг)

Порядок: **сверка цифр → линтер → публикация.**

### 4.1. Сверка цифр

```bash
node tools/fetch-act.mjs <eoNumber>
```

Скрипт скачает в `out/acts/<eoNumber>/`:
- `page-01.png`, `page-02.png`… — постраничные сканы официального опубликования;
- `act.pdf` — официальный PDF;
- `meta.json` — номер, даты, регистрация в Минюсте, число страниц.

Откройте PNG и сверьте **каждую** цифру в статье:
- номера статей и пунктов;
- ставки, лимиты, пороги;
- сроки и даты вступления в силу;
- суммы в примерах (пересчитайте на калькуляторе).

**Важно:** PDF на портале — скан без текстового слоя, извлечь из него текст
программно нельзя. Сверяйте по страницам PNG.

Тексты разъяснений ФНС и Минфина — на `nalog.gov.ru` и `minfin.gov.ru`.

### 4.2. Линтер

```bash
node tools/lint-article.mjs src/NN-тема.md
```

**Блокирующие замечания (`✗`) — статья не выходит:**
- нет блока `:::example` с разбором расчёта;
- меньше 8 чисел в тексте;
- нет ссылок на нормы;
- нет ни одной ссылки на первоисточник;
- неопределённость рядом с числом («около 1000 ₽»);
- нет дисклеймера.

**Замечания (`!`) — на ваше усмотрение:** канцелярит, длинные предложения,
термин без пояснения, мало слов, мало блоков с примерами.

### 4.3. Публикация

```bash
node tools/publish-article.mjs src/NN-тема.md
```

## 5. Оформление страницы

Делается автоматически, вам остаётся знать:

| Элемент | Откуда берётся |
|---|---|
| Заголовок страницы (H1) | `# Заголовок` из Markdown |
| Описание для поиска | `@desc` |
| Текст под заголовком | `@lead` |
| «Обновлено» | дата публикации — ставится автоматически |
| Пометка об ИИ | добавляется автоматически: «Материал подготовлен с помощью ИИ и проверен редактором» |
| Микроразметка Schema.org | добавляется автоматически |
| Якоря у разделов | добавляются автоматически |
| Блок «Другие разборы» | подбирается по совпадению слов |
| Ссылка в sitemap.xml и RSS | добавляется автоматически |
| Карточка на главной | добавляется автоматически |

## 6. Правовые рамки (соблюдать обязательно)

- **243-ФЗ от 26.07.2026, ст. 9** — маркировка материала, созданного с помощью ИИ.
  Для обычного текстового блога формального требования нет, пометку оставляем
  добровольно. <https://rg.ru/documents/2026/07/31/fz243-dok.html>
- **Ч. 9 ст. 13.15 КоАП РФ** — распространение заведомо недостоверной информации
  под видом достоверной. Отсюда правило: ни одной цифры без первоисточника.
  <https://sudact.ru/law/koap/razdel-ii/glava-13/statia-13.15/>
- **ГК РФ ст. 1228** — авторское право: автором признаётся лицо, создавшее
  результат творческим трудом. Пересказ чужих текстов прав не создаёт —
  поэтому используются только официальные документы.
- **38-ФЗ ст. 18.1** — маркировка рекламы (ЕРИР): нужен `erid`, когда появится
  реклама.
- **Поисковики.** Google: массовая генерация страниц — *scaled content abuse*
  (<https://developers.google.com/search/docs/essentials/spam-policies>).
  Яндекс: «малополезный контент»
  (<https://yandex.ru/support/webmaster/ru/threat/useless-content>).

**Практический вывод:** статья = уникальный разбор + расчёты + ссылки +
живой автор. Не пересказ закона.

## 7. Ритм

- **Одна статья в день.** Три в неделю — минимально, одна в день — рабочий режим.
- **Публикуйте утром**: бухгалтер проверяет отчётность до начала дня.
- Один разбор — один день. Не публикуйте два за день, если не готовы
  вычитать оба.
- По выходным можно не публиковать: аудитория проверяет отчётность в рабочие дни.

**Реальность ограничения.** Три статьи в неделю — это 100–120 строк текста
с проверкой. Одна в день — 7 в неделю, то есть 200–280 строк. Это много.
Проверка цифр — самая медленная часть. Если не успеваете — лучше три статьи
в неделю с реальной проверкой, чем семь с формальной.
